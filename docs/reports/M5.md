构建/测试：Linux 与 Windows 原生 `fmt --check` ✓、`clippy --workspace --all-targets -D warnings` ✓、`cargo test --workspace` 全绿（Windows 443 项，

本里程碑实现
- vendored `llama-cpp-sys-2`/`llama-cpp-2` 0.1.159 + llama.cpp master（支持 `gemma-embedding2`，裁剪到 42 MB）（ADR-020）；Windows 需 CMake 与 libclang。
- `fnc-semantic`：Embedder trait、llama.cpp 查询/索引双上下文、Matryoshka 截断、空闲卸载、任务前缀、`models.toml` 注册表、分块器（文件名去噪、句边界 + 重叠、代码窗口）、usearch int8 余弦库（按文本哈希复用块、校验和、压缩）、后台语义索引器（范围、防抖、CPU 限额、状态）、RRF（ADR-021）。
- 查询：`sem:` `semantic:` `semname:` `semcontent:` `semcode:` `semimage:`、`sem:>0.6 文本`、`sem-min-score:`、`sem-top:`、`?sem:`；顶层语义项在字面条件之后执行（< 5000 候选逐个精确打分，否则 ANN 并逐步扩大 k），嵌套项为 ANN 命中集合。
- 应用：设置页"语义搜索"、向导（范围、模型下载 + SHA-256 校验）、搜索框旁"语义"开关（等同 `?sem:`，RRF 融合）、状态栏、自动出现的"相关度"列（语义查询默认按相关度排序）、预览定位命中段落、`semantic_gpu_layers` + `vulkan` 特性。
- 工具：`sem-eval`、`tools/sem-corpus.py`。

在 Windows 实测中发现并修复
1. usearch 的 numkong 内核在中文代码页（GBK）下用 MSVC 编译失败（UTF-8 注释吞掉换行）→ 关闭 numkong，使用 usearch 自带 i8 余弦。
2. llama.cpp 绑定需要 libclang（bindgen）与 CMake → 写入构建说明。
3. 语义查询沿用名称排序，相似度高的结果不在前面 → 语义查询自动按相关度排序，恢复字面查询时还原原排序。
4. 自动出现的相关度列不显示排序箭头 → 修复。

已知差异 / 未做
- 索引吞吐低于 SPEC 的 ≥ 20 块/秒（CPU 算力所限）；GPU 需 `vulkan` 特性构建。
- `semimage:`（以文搜图）未实现：`llama-cpp-2` 未暴露嵌入模型的多模态路径（SPEC `[MAY]`）。
- 后台线程未设 THREAD_MODE_BACKGROUND_BEGIN（llama.cpp 工作线程不继承），CPU 限额以线程数实现。
- 关闭语义搜索后进程内存不回落到启用前水平，重启恢复。
- 以上均已写入第 2 章 §9 差异表与 ADR-021。

DECISION 记录（主代理已决定，不阻塞）
- 默认维度 256、阈值 0.45、候选 200、CPU 限额 25%、空闲卸载 10 min（SPEC 默认值）。
- 模型不随安装包分发（300 MB），首次启用时由向导从 Hugging Face 下载并校验 SHA-256；离线环境可手动放到 `models\` 或指定 `semantic_model_path`。
