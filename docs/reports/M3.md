构建/测试：Linux `fmt --check` ✓、`clippy --workspace --all-targets -D warnings` ✓、`cargo test --workspace` 全绿；
  Windows 目标交叉 `clippy`（除 bench/fnc-semantic/sem-eval）✓；Windows 原生 `cargo test --workspace --release` 全绿，
  另跑 `--ignored ntfs_property_and_content_index`（真实卷，管理员）通过；真实桌面 `fennec.exe -instance m3` 手工验证。

本里程碑实现（应用侧，库在此前合入）
- 设置（`properties`/`content` 两页，选项窗口自动生成）：属性名、文件夹、扩展名、快速排序、未索引属性按需读取、
  慢速搜索上限（默认 10,000 个文件）；内容索引开关、文件夹、扩展名（默认与 SPEC 一致）、单文件上限 4 MB、总大小上限、
  Office/PDF 解析、未索引内容按需读取。两项索引默认关闭：后台线程休眠、实时变更不收集，零开销。
- `fnc-app::stores`（ADR-016）：句柄只建一次，所有搜索/新窗口复用同一组 `Arc`；`IndexHooks` 在发布前挂接
  `props.fnx`/`content.fnx`（与发布的 id 空间一致，首帧即可搜索）、压缩后 `remap`、元数据完成后全量扫描、
  USN/文件夹监视变更（大小或修改时间变 → 重新提取；仅改名 → 只重判范围；移动文件夹 → 子树；删除 → 清理行）、
  与索引同一快照保存（周期、`-save-db`、退出）；`hashes.fnx` 启动时加载。后台线程 `THREAD_MODE_BACKGROUND_BEGIN`，
  每批 64 个文件无锁提取，短写锁插入，配置变更即取消，状态栏显示“属性/内容索引：已完成 / 总数”。
- 引擎接线：`SearchOptions::{props, content, hashes, on_demand, slow}`；新增 `SlowPolicy::read_uncovered`，应用设为
  `false`：已索引属性与内容索引是权威的，范围外文件不读磁盘（否则 `width:>4000` 会在 39 万条目上读 10,000 个无关文件）。
- `fnc-platform::props`：`SHGetPropertyStoreFromParsingName` + `IPropertyStore` 的 `PropertyProvider`，单位换算
  （100 ns→ms、bps→kbps、帧率/1000、分级→星、GPS 度分秒→度）；STA 按线程初始化；另加后台线程模式与 `GetACP`。
- 界面：约 95 个属性列（列选择器“属性列”子菜单，已索引的排前），可排序（单击/Ctrl+单击，`SortKey::Property`），
  列/排序设置写属性名；标题与是/否、像素、星级本地化；`dupe:` 结果自动显示“重复组”列；预览对 `content:` 用提取文本
  （已索引优先，否则按需提取，支持 docx/pdf）、高亮全部命中并滚动到首个命中，并列出已索引属性；
  `ExecStats::warnings`（未索引、慢速上限、语义）本地化；`-sort width` 命令行。
- kittest：属性列显示/排序、`width:>4000`、重复组列可见、`content:` 预览高亮与滚动、慢速上限警告、选项页列出设置；
  `stores` 单测覆盖提取、变更、保存/重载、压缩 remap、范围（祖先匹配/通配）、关闭内容索引。

在 Windows 实测中发现并修复
1. “重复组”列追加在最后：占满剩余宽度的“大小”列把它挤出可视区（kittest 只查到无障碍标签）→ 插在第一列之后，
   列宽按列 id 记忆；kittest 改为断言列头矩形在可视区内。
2. 属性扩展名为空（全部文件）时，范围扫描为 39 万个文件逐个拼完整路径匹配文件夹：每次扫描 390–530 ms
   → 字面文件夹先在索引中解析为条目，按祖先判断，扫描降到约 56 ms。
3. 库的慢速路径会对未覆盖条目逐个读盘：IDX-08/09 在真实卷上会读满 10,000 个文件并报“慢速搜索已停止”
   → `SlowPolicy::read_uncovered`，应用让索引成为权威（`notindexed:` 仍可强制读取）。
4. 测量方法：重复同一查询会命中引擎的结果复用（13 µs，不代表真实执行）→ 计时轮次之间插入其他查询并关闭复用。

已知差异 / 未支持（均已写入 SPEC 第 2 章 §9）
- IFilter 不实现（需 COM 隔离进程）；内容只有纯文本/HTML/OOXML/PDF。
- 权威索引：在范围内但尚未提取的文件，以及范围外文件，对已索引属性/`content:` 视为无值（与 Everything 的包含文件夹一致）。
- `property_fast_sort` 接受但不建额外结构（属性列排序 100 万条 58 ms）。
- 文件夹索引条目每次启动 FRN 不同，重启后其属性/内容在后台重新提取（NTFS 卷不受影响）。
- Windows 属性系统只补内置提取器缺失的属性；非 Windows 平台无兜底。
- 应用运行期不压缩索引（只在发布前压缩）；`IndexHooks::compacted` 已接好，墓碑在长时间运行中累积。
- 提取进行中每秒刷新一次当前搜索：不涉及属性/内容的查询也会重跑（结果复用被存储代次打断）。
