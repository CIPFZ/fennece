在 Windows 实测中发现并修复
1. 新标签页与新窗口在索引变化后不刷新：索引器只通知第一个视图的引擎（删除文件后新标签里留下“…”行）。改为每帧检查结果代号与索引代号，过期且无进行中的搜索时刷新（≤ 每 250 ms 一次）。
2. 索引写锁或属性库锁被占用的那一帧画出的行显示“…”且不再重绘：现在会在 30 ms 后重绘。
3. 查找栏测试在 Windows 上偶发失败（晚到的刷新使行号变化）：改为按条目断言。

已知差异 / 未做
- 自定义列不可排序（逐行求值，未进入排序引擎）。
- 撤销不记录剪贴板/拖放的移动与复制（Shell 不回报结果）以及永久删除。
- ETP/FTP 服务器未实现（`[MAY]`）。

各里程碑遗留 DECISION 的处理（主代理决定）
| 来源 | 问题 | 决定 |
|---|---|---|
| M3 | 已索引属性/内容库是否权威（库外文件不读盘）| 是（IDX-08/09 即时）；`notindexed:` 仍读盘 |
| M3 | IFilter | 不做（需隔离进程宿主），记入差异表 |
| M3 | 文件夹索引的文件号不稳定，重启后重新提取属性 | 保持现状并记录；NTFS 卷不受影响 |
| M4 | 运行中通过 IPC 重建数据库 | 保持拒绝，需要时 `-reindex` 重启 |
| M4 | HTTP 密码存储 | 保持明文（受文件权限保护；默认关闭、仅回环、必须设密码），记入差异表 |
| M4 | 真实 Everything 退出后兼容窗口是否补建 | 已实现：每 30 s 重试 |
| M5 | 模型是否随安装包分发 | 不分发（300 MB），向导下载并校验 SHA-256 |
