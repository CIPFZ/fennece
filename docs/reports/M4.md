本里程碑实现（应用接线）
- `count:<max>` 结果上限移入 fnc-query/fnc-exec（`FuncId::Count` → `SetKind::Limit`，作为最后一个集合函数在排序后
  截断），UI、IPC、HTTP、fes、兼容层一致；`count:` 后不是纯数字时仍为比较修饰符；删除 fnc-ipc 的 `extract_count_limit`。
- `fnc-app/src/ipc_host.rs`：`AppHost`（选项、筛选器、书签、索引状态镜像；运行计数变化刷新所有视图；
  `DeleteRunHistory`/`SaveDb`/`Update`/`Exit`/命令行；管道客户端须同会话且完整性 ≥ Medium）。
- `fnc-platform`：`compat`（独立线程的隐藏顶层窗口、查询在工作线程执行并由其回发 `WM_COPYDATA`、检测真实
  Everything 冲突、广播 `EVERYTHING_IPC_CREATED`）、`session`（会话 ID / 完整性级别，带 SAFETY 注释）。
- `fnc-app/src/servers.rs`：IPC 管道、兼容窗口、HTTP 在 `fennec-servers` 线程按设置启动/停止（只重启变化部分），
  状态栏显示 HTTP 地址或错误；选项“服务器”页由设置元数据生成（密码掩码）。
- 文件 → 导出与“复制为 CSV/EFU”改用 `fnc_ipc::export`（按扩展名 EFU/CSV/TSV/JSON/M3U/M3U8/TXT，CSV/TSV/JSON
  用当前可见列），删除应用内重复的写出代码。ADR-034；SPEC 第 2 章 §9 新增 3 行。

在 Windows 实测中发现并修复
1. es.exe `-exit` 向窗口发送 `WM_CLOSE` 并等待进程结束：最初窗口被销毁而应用不退出，es 一直挂起
   → 客户端的 `WM_CLOSE` 视为退出请求，应用自身用私有 `WM_APP` 消息关闭窗口。
2. 搜索框中输入 `/http_port=8081` 后按 Enter 被键位表当作“打开”吞掉，行内命令从未执行（M2 起的问题）
   → 搜索框内容以 `/` 开头时 Enter 交给行内命令；kittest 覆盖。
3. 行内命令的回显会把 `http_password` 明文显示在状态栏 → 密码类设置回显为 `••••`；HTTP 启动错误本地化。
4. `-instance` 非默认实例以标准用户运行时连接不到服务（服务只为默认实例安装）→ 退回文件夹索引，记入差异表。

仍待处理 / 已知差异
- `REBUILD_DB` / `Op::Rebuild` 在运行中的应用里返回失败（索引源启动时固定，需 `-reindex` 重启），已记入差异表。
- Everything 兼容窗口的管理命令不做会话/完整性校验（窗口消息不跨会话，`EVERYTHING_WM_IPC` 不带发送者）。
- HTTP 密码以明文存于 settings.toml（仅受文件权限保护）；es.exe 自身输出到控制台时中文按代码页显示（非 Fennec 问题）。
- 与真实 Everything 同时运行时不创建兼容窗口，状态栏提示；Everything 退出后需重新切换 `everything_ipc` 才会创建。
